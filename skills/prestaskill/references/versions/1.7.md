# PrestaShop 1.7

Tout ce qui est marqué *(à vérifier)* : grep dans le core ou WebFetch la doc avant de l'utiliser.

PHP 5.4 → 7.4 selon mineure (voir php.md) · Symfony 2.8 (≤ 1.7.3) puis 3.4 · Thème défaut : classic · Thèmes enfants : oui · BO : Smarty + Twig (pages migrées) · Traductions : `$this->trans()` à partir de 1.7.6, sinon `$this->l()` · Doc : https://devdocs.prestashop-project.org/1.7/

- Symfony 3.4 dans le BO, migration progressive : certaines pages sont Symfony (Twig), d'autres legacy. Vérifier dans `src/PrestaShopBundle/Resources/config/routing/` si une page est migrée avant de choisir hook legacy vs hook Grid/Form.
- Hooks Grid `action<Grille>GridDefinitionModifier` : 1.7.5+ ; hooks Form `action<Formulaire>FormBuilderModifier` : 1.7.6+ (vérifié dans le core 1.7.5.0 / 1.7.6.0). Seulement sur les pages déjà migrées.
- Controllers admin Symfony dans un module (`config/routes.yml`) : 1.7.5+. Commandes console de module : 1.7.5+.
- Services du module : `config/services.yml` accessible au conteneur Symfony depuis 1.7.3 ; depuis 1.7.6, `config/admin/services.yml` et `config/front/services.yml` pour les contextes legacy BO / front.
- Front : `registerStylesheet` / `registerJavascript` dans `hookActionFrontControllerSetMedia`.
- Widgets : `implements WidgetInterface` (`renderWidget`, `getWidgetVariables`), appelables via `{widget name='module'}`.
- Fiche produit BO : ancienne page (Twig + JS), extension par `displayAdminProductsExtra` (onglet Modules) et `displayAdminProductsMainStep…` ; sauvegarde par `actionProductUpdate` / `actionObjectProductUpdateAfter`.
- Fiche commande BO : page Symfony depuis 1.7.7 → `displayAdminOrderMain`, `displayAdminOrderSide`, `displayAdminOrderTop`, `displayAdminOrderTabLink` / `displayAdminOrderTabContent` (`$params['id_order']`). Avant 1.7.7 : `displayAdminOrder`, `displayAdminOrderLeft` / `Right`, `displayAdminOrderTabOrder` / `ContentOrder`, plus appelés ensuite *(à vérifier)*.
- Fiche client BO : page Symfony depuis 1.7.6 → `displayAdminCustomers` toujours appelé, champs du formulaire par `actionCustomerFormBuilderModifier` *(à vérifier)*.
- Debug local : `_PS_MODE_DEV_` à `true` dans `config/defines.inc.php` (ou BO > Paramètres avancés > Performances). Jamais en production.
- Cache : `php bin/console cache:clear` ou `rm -rf var/cache/*` (contient `class_index.php`). Si « Smart cache » CSS/JS est actif (BO > Performances, `PS_CSS_THEME_CACHE` / `PS_JS_THEME_CACHE`), vider **aussi** les assets combinés, que `cache:clear` ne touche pas : `php -r "require 'config/config.inc.php'; Media::clearCache();"` depuis la racine de la boutique (ou BO > Performances > Vider le cache).

Module multi-versions : voir modules.md § Module compatible multi-versions.
